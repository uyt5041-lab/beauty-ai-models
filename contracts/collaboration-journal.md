# 협업일지 작성 계약

계약 ID: BEAUTY-JOURNAL-001 · 버전: 4 · 적용일: 2026-10-23

사용자 요청으로 정한 이 브랜치의 일지 작성 규칙이다. 코드잇 고급프로젝트 가이드의 Daily 협업일지 양식을 2026-10-22에 확인해 항목과 작성 원칙을 정리했다. 교육자료의 원문, 예시 답변과 비공개 링크는 복제하지 않는다.

## 적용 범위

`박지수_협업일지` 브랜치의 신규 일지와 사용자가 수정 요청한 일지에 적용한다. 2026-10-22 일지부터 이 계약을 따른다. 과거 일지는 당시 기록으로 보존한다. 모델 코드와 원본 구현 체크리스트는 `plan/models`에서 관리하며 두 브랜치를 병합하거나 PR을 만들지 않는다.

## 본문 필수 형식

본문은 다음 8개 항목을 순서대로 작성한다. Markdown과 HTML의 내용은 같아야 한다.

| 순서 | 항목 | 기록할 내용 |
| --- | --- | --- |
| 1 | 날짜·이름·팀명 | 한국 날짜, 작성자와 팀. 기록 기간 및 수집 기준 시각도 명시 |
| 2 | 오늘의 역할과 구체적인 작업 | 시작할 때의 목표, 수행한 일과 못 한 일, 코드·문서·실행 근거 |
| 3 | 오늘 작업 완료도 | 0·25·50·75·100% 중 하나와 이유. 전체 프로젝트와 당일 목표를 구분. 본인 평가가 없으면 잠정 평가임을 표시 |
| 4 | 협업 제안·피드백 | 어떤 의견을 누구에게 어떤 자료로 제시했는지. 문서 작성·공유·상대 확인을 구분 |
| 5 | 인사이트·문제 | 실험이나 구현에서 배운 점, 오류와 수정, 남은 한계 |
| 6 | 일정·협업의 어려움 | 지연·미합의·의존성과 대응. 확인하지 않은 감정이나 팀원 행동은 쓰지 않음 |
| 7 | 발표·커뮤니케이션 기여 | 자료 제작, 공유, 설명, 시연 준비 등 실제 수행한 일. 없으면 없다고 기록 |
| 8 | 내일 목표 | 우선순위, 필요한 입력, 확인 가능한 완료 기준 |

## 근거와 완료 체크

- 개인별로 매일 목표와 마무리 기록을 남긴다. 정돈된 문장보다 구체적인 작업, 고민, 실수와 팀 기여를 우선한다.
- TODO 원본, 구현, 테스트 기록, 실제 모델 실행, Git 게시, 팀 인수를 구분한다. 테스트 개수는 중복 합산하지 않는다.
- 원본에 완료 표시와 근거가 함께 있는 항목만 완료 목록에 옮긴다. 미완료 체크를 일지 작성 때문에 완료로 바꾸지 않는다.
- 예정일, 실제 완료일, 커밋 시각, 기록 시각을 따로 쓴다. 시각을 모르면 미확인으로 남긴다.
- 전체 TODO와 이후 예정 항목까지 계획 목록에 모두 표시한다. 체크는 보고일(오늘)까지 계획된 항목 중 완료한 항목에만 한다. 이후 예정 항목은 먼저 끝냈어도 일지에서 미리 체크하거나 완료 성과로 쓰지 않는다.
- 범위 안에서 끝난 항목은 전부 체크하고, 아직 끝나지 않은 항목은 빈 체크로 남긴다. 전체가 끝나지 않았는데 모두 완료로 바꾸지 않는다.
- 보고일 범위를 맞추기 위해 실제 완료일이나 계획일을 바꾸지 않는다. 원본 코드·개발 기록과 체크 상태는 보존한다.
- 원본 TODO가 구현 상태의 기준이다. 일지의 완료 표는 관측 시점의 기록이며 진행 상태를 이중 관리하는 체크리스트로 사용하지 않는다.
- 날짜별 전체 완료 항목·검증·스키마는 별첨으로 연결할 수 있다. 본문 8항목은 생략하지 않는다.
- 기술 실행 성공을 실사진 품질, 외부 API 성공 또는 사용자 승인으로 표시하지 않는다. 로컬 모델 실험과 현재 외부 API 계획을 구분한다.

## 저장과 게시

날짜별 `worklogs/YYYY-MM-DD/`에 Markdown과 HTML을 두고 README 인덱스에서 연결한다. 기존 파일의 형식 수정은 같은 일지 ID와 URL을 유지하고 이전 본문을 Git 이력 또는 별첨으로 보존한다.

사용자가 게시를 요청한 범위만 일반 push한다. 원격을 먼저 확인하고 fast-forward만 허용한다. 브라우저에서 인덱스 링크를 눌러 날짜·제목·8항목·별첨을 확인한다. API 키, 모델 가중치, 생성 이미지, 로컬 절대 경로와 교육자료 원문은 공개하지 않는다.

## 이번 적용

2026-10-22의 기존 스키마 중심 보고서를 8항목 일지로 고친다. 스키마 본문은 같은 날짜의 `schema-draft-details.md`에 보존한다. 오늘까지의 계획 범위에서 완료한 26개만 원본 줄번호와 검증 기록을 붙여 체크한다. 이후 예정 단계는 전체 계획에만 표시하며 완료 체크와 성과에서 제외한다.

## 전체 목록과 진행률 바

전체 TODO 목록을 날짜별 일지와 README에서 연결한다. 완료 항목만 나열하지 않는다. 전체 원본 체크 항목 수를 분모로, 보고일까지 계획된 항목의 확인된 완료 수를 분자로 사용한다. 같은 항목을 요약·별첨·다른 문서에서 중복 집계하지 않는다.

Markdown에는 progress.svg를 넣고 HTML에는 실제 progress 요소 또는 같은 데이터의 SVG 바를 넣는다. 완료 수·전체 수·퍼센트를 글자로도 표시한다. 현재 필수 API/SSOT 묶음은 따로 표시하되 전체에 다시 더하지 않는다.

자동 체크 진행률은 일지 반영 기준이며 제품 완성률이나 본인의 당일 자기평가와 다르다. 미래 계획은 미체크로 보이며, 그 표시만으로 실제 구현이 미완료라는 뜻으로 해석하지 않는다.

반복 작성은 [beauty-ilji 스킬](../skills/beauty-ilji/SKILL.md)을 따른다. 원본 TODO의 고정 커밋을 읽어 전체 목록과 bar를 생성하고 숫자·날짜 범위·링크를 확인한다.


## 2026-10-23 · 공유용과 실제 체크의 분리

공유용 TODO는 날짜별 읽기 전용 스냅샷으로 관리한다. 실제 구현 여부는 `plan/models/docs/imageTodo.md`와 그 검증 근거에서 관리한다. 앞당겨 끝낸 실제 체크를 보고일에 맞추어 되돌리지 않는다. 공유용의 미래 항목은 미체크로 남기며, 이를 구현 미완료 판정으로 쓰지 않는다.

분모는 해당 날짜에 고정한 원본의 전체 항목 수다. 130개로 고정하지 않으며 새 항목이 추가되면 수와 기준 커밋을 함께 표시한다. 오늘 원본은 150개이고, 보고일까지의 완료 체크는 42개다. 이전 날짜의 원본과 숫자는 당시 기록으로 보존한다.

미게시 WIP를 공유 완료에 합산하지 않는다. 모델·제품 품질·청구액·팀 인수를 문서 게시와 구분한다. 원본 코드·공유 checkout·index를 보존하고 협업일지 브랜치에만 일반 push한다.
