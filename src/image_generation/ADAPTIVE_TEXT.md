# 배경판 없는 자동 색상·위치 합성

기존 `compose_ad_png`에 `adaptive`를 주면 선택 적용한다. 이미지·카피·글꼴·글자 크기와
A 허용 영역을 유지하고, 영역 안에서 글자 묶음만 이동한다. 인물이나 제품 의미를 이해하는
객체 탐지가 아니라 픽셀 변화에 기반한 경계 회피다. 프론트·서빙 DTO는 바꾸지 않는다.

```python
from src.image_generation import compose_ad_png
from src.image_generation.adaptive_typography import AdaptiveTypographyOptions

result = compose_ad_png(
    approved_composition_input,
    font_path=licensed_font_path,
    adaptive=AdaptiveTypographyOptions(
        clearance_px=12,       # 검출 경계에서 떨어질 거리 n, 최종 이미지 px
        movement_axis="vertical", # 기본값. 가로 정렬을 고정하고 상하만 이동
        inset_px=0,            # A 영역 가장자리에서 추가로 비울 거리
        max_move_px=140,       # 각 축에서 허용할 최대 이동
        edge_threshold=24,    # 6px 간격의 평활 RGB 변화 기준(0~255)
        median_delta=64,      # 영역 대표 RGB 중앙값과의 채널별 차이 기준
        min_component_area_px=96,
        min_component_span_px=80,  # 작은 물방울 반짝임·질감 제외
        step_px=4,
        max_color_checks=64,
    ),
)
```

## 처리 순서

1. 리사이즈한 최종 이미지의 각 문구 영역에서 RGB 중앙값을 구한다.
2. 평활 이미지의 급격한 색 변화와 대표색에서 크게 벗어난 영역을 찾는다.
3. 작은 연결 성분을 제외한다. 남은 경계를 `n px`만큼 사각형 방식으로 확장한다.
4. 확장된 경계와 글자 묶음의 사각형이 겹치지 않는 위치를 원래 위치에서 가까운 순으로 찾는다.
5. 같은 계열·인접색·보색과 중성색을 포함한 최대 11개 색 후보로 실제 글자 내부 대비를 검사한다.
6. 경계 이격과 대비 4.5:1을 함께 만족하는 위치를 선택한다. 배경판은 추가하지 않는다.

글자 중심부의 불투명도 192/255 이상인 픽셀을 검사한다. 가장자리의 모든 안티앨리어싱
픽셀까지 대비를 보장하는 검사는 아니다. 제품과 배경의 색이 비슷하거나 작은 물체라면
검출에서 빠질 수 있다. 색 차이가 큰 배경 무늬는 반대로 장애물로 잡힐 수 있다.
**검출 경계 회피 성공을 의미적 제품 가림 방지 성공으로 해석하지 않는다.**

옵션은 최종 1080px 폭의 이미지 좌표를 기준으로 한다. 기본 inset은 6px이다.
이번 5장 비교에서는 A 허용 영역을 끝까지 활용하도록 `inset_px=0`을 공통 적용했다.
검출 경계 이격 `clearance_px=12`와 A의 바깥쪽 여백은 유지했다.

영역 안에서 조건을 만족하는 자리를 찾지 못하면 `COMPOSITION_NO_SAFE_POSITION`으로 실패한다.
상하 전용 모드에서는 가능한 자리가 없더라도 좌우 이동으로 대체하지 않는다.
`movement_axis="both"`는 과거 상하좌우 실험을 재현할 때만 명시한다.

사용자가 실패 시 아래로 강제 배치하도록 선택한 경우에만
`fallback_lower=True, fallback_shift_px=48`을 지정한다. 기본은 `False`이다.
이 경우 검사 실패를 숨기지 않고 가로 중심을 고정한 채 지정 거리만큼 아래로 이동한다.
글자 전체는 A 허용 영역 안으로 제한하며 네모 배경판은 추가하지 않는다.
영수증의 `forced_lower_fallback`, `clearance_passed`, `contrast_passed`와 경고를 확인한다.
대비 목표에 못 미쳐도 이 명시적 선택에서는 결과를 반환하며 `text_contrast_passed=False`를 유지한다.

2026-11-11 후속 5장 비교: P1/P3에만 이격 4px와 하단 대체 배치를 적용했다.
두 CTA 모두 가로 이동 0px·아래 48px로 강제 배치됐다.
P1은 이격 미달, P3은 대비 약 4.29:1로 목표 4.5:1 미달이다. P2/P4/P5는 정상 탐색으로 합성했다.
대비를 낮추거나 배경판을 넣거나 허용 영역 밖으로 나가는 처리는 하지 않는다.
명시적 `region.background`도 선택 모드에서는 거절한다.

영수증의 `position_check`에 이동량·후보 수·검사 수·검출 경계 겹침 여부,
`color_check`에 색 후보·선택색·대비·배경판 없음이 기록된다.
`adaptive_options`에 실행한 설정을 남긴다. 기존 `protected_regions` 계약은 그대로다.

## 2026-11-11 로컬 비교

아래 표는 이전 상하좌우 실험이다. 사용자 피드백 이후 기본 모드를 상하 전용으로 바꿨다.
동일한 5장에 이격 12px·대비 4.5:1을 적용한 상하 전용 검증에서 P2/P4/P5는 합성됐고,
P1/P3은 허용 영역 안에 조건을 만족하는 자리가 없어 실패했다. 가로 이동으로 우회하지 않았다.
글자 크기·카피·A 영역은 바꾸지 않았으며 추가 API 호출은 없다.

14디멘션으로 생성했던 5장의 생성 원본을 재사용했다. 카피·글꼴·크기는 동일하며 API 호출은 0회다.

| 제품 | CTA 이동(오른쪽/아래, px) | 배경판 |
|---|---:|---|
| P1 모다모다 | +96 / +32 | 없음 |
| P2 아벤느 | 0 / -12 | 없음 |
| P3 스킨푸드 | +32 / +54 | 없음 |
| P4 클리오 | 0 / 0 | 없음 |
| P5 moumou | 0 / 0 | 없음 |

제목·서브는 원래 위치를 유지했다. P3 CTA는 하단 선반 면의 대비를 확보하려 검정을 선택했다.
다른 문구에는 갈색·남색·짙은 보라 등 후보가 선택됐다. 디자인 선호는 사용자 검토 대상이다.
