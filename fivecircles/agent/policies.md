# 프로젝트 정책

- 개발 계약은 architecture/spec 또는 architecture/contract, 원본 작업 항목은 docs의 TODO에 둔다.
- requirements에는 확인한 요구사항과 미합의 제안을 구분해 둔다. 기록만으로 합의가 되지는 않는다.
- 실제 완료 증거가 있는 항목만 체크한다. 프레임워크 설정으로 모델 TODO가 완료되지는 않는다.
- 비밀값·환경 설정·생성 이미지·모델 가중치·테스트 캐시는 기존 .gitignore에 따라 제외한다.
- API/스키마 변경 시 입력 hash, revision, 응답 유실·재시도, 늦은 결과를 검토한다.
- 보호 규칙을 바꿀 때 변경 이유·범위·되돌릴 방법을 work/worklog에 남긴다. 사용자 승인이 이미 있는 작업에 중복 승인을 요구하지 않는다.
- 커밋 제목은 `docs: ...`, `chore: ...`, `feat: ...`, `fix: ...`처럼 목적이 드러나게 쓴다.
