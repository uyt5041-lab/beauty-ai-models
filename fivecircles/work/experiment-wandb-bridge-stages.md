- 오프라인 실행 → 새 결과 수집 → W&B 패키지, 자동 후처리 순서, 중복 동일성, 업로드 실패 시 원본 보존, 미확인 비용을 검증했다.

## 2단계 실패와 중단

- iCloud 앨범 47장 중 아벤느 Cicalfate+ 100ml 정면·측면·뒷면을 화면에서 확인했다. 각각 IMG_1045.JPG, IMG_1046.JPG, IMG_1047.JPG다.
- 제품 전체가 보이고 손·가격표가 없어 입력 후보로 골랐다. 최종 광고 품질을 승인한 것은 아니다.
- 화면에 표시된 공유 사진 3개를 비공개 로컬 uploads 폴더에 저장했다.
- Pillow 검증의 `im.format == 'JPEG' and im.size == (1536, 2048)` 조건에서 `AssertionError`가 발생했다.
- 실제 파일의 어떤 속성이 달랐는지는 추가 조사하지 않았다. 사용자 지시에 따라 변환·재다운로드·수리·재검증 없이 중단했다.
- 사진 검증과 출처 manifest는 완료되지 않았다. 기존 미리보기는 유지하며 새 미리보기는 생성하지 않았다.
- 실제 이미지 API 0회, W&B 신규 업로드 0건. Git 커밋·푸시·PR 없음.

## 2026-10-23 사용자 재개 요청 후 판정

- 사용자 요청: 준비를 마치면 실제 1회 호출하고 평가한다. 단계 실패 시 중단 규칙은 유지한다.
- 원인 확인: iCloud 3개 파일은 확장자 JPG이지만 Pillow에서 MPO로 읽힌다. 크기는 모두 1536×2048이다.
- 원본을 보존하고 frame 0을 PNG로 옮기는 입력 전처리를 시도했다.
- 새 검증 스크립트가 픽셀을 읽은 뒤 같은 이미지 객체의 verify()를 호출해 `RuntimeError: verify must be called directly after open` 발생. 사진 손상 판정이 아니라 검증 코드의 순서 오류다.
- FAILED_STOPPED. 수리/재검증은 하지 않았고 독립 준비 검토도 중단했다. 새 미리보기·실제 생성·평가는 SKIPPED_AFTER_FAILURE다. 이미지 API 0회, W&B 신규 업로드 0건.


## 2026-10-23 · 검증 코드 수정 후 실제 1회 생성·평가 완료
