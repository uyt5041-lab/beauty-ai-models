# 새 실험 실행 결과의 W&B 연결

작성일: 2026-10-23. 구현 전에 정한 범위다.

- 입력: 고정 `plan.json`, 최종 `report.json`, 각 작업의 영수증과 입력/출력 이미지다.
- 출력: 기존 W&B 패키지 형식과 별도 `wandb-sync.json`이다. 이미지 실행 보고서는 바꾸지 않는다.
- 명시적으로 W&B 기록을 켠 실행은 로컬 저장 후 자동 업로드한다. 기존 결과만 다시 등록하는 명령도 제공한다.
- W&B 등록은 이미지 생성·편집 API를 호출하지 않는다. 실패해도 이미지 작업을 다시 실행하지 않는다.
- 같은 작업 ID와 같은 내용은 기존 원격 기록을 다시 검증한다. 같은 ID의 내용이 다르면 중단한다.
- 원격 이미지·프롬프트·메타데이터를 다시 읽어 일치할 때만 `READBACK_VERIFIED`로 판정한다.
- 준비만 한 결과, 모의 실행, 미실행 후속 작업은 실제 API 실험으로 집계하지 않는다.
- 실패·응답 미확인·대기 종료는 원래 상태를 보존한다. 시도 슬롯은 실제 POST나 청구 증명이 아니다.
- 제품/참고 역할과 순서, 당시 프롬프트·버전·시간·사용량을 보존한다. 새 실행에 과거 B12 단가를 자동 적용하지 않는다.
- 이번 사진 작업은 iCloud에서 읽고 선별한 뒤 새 호출 전 미리보기를 만드는 범위다. 생성 API 호출은 0회다.

사용 예: “실행 후 W&B에도 남겨” → `execute ... --wandb --wandb-entity TEAM`.
등록 실패 후 예: “생성은 다시 하지 말고 저장된 결과만 올려” → `sync-wandb --plan ... --expect-sha256 ... --entity TEAM`.

검증 실패 시 수리/재실행 없이 중단한다. 사용자 요청이 스킬의 재시도 안내보다 우선한다.
