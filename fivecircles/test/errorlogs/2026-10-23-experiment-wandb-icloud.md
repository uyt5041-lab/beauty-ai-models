- 날짜: 2026-10-23.
- 단계: W&B 연결 통과 후 iCloud 사진 선별/파일 검증.
- 실행: 프로젝트 Python의 Pillow로 다운로드 파일을 열고 JPEG 형식·1536×2048 크기·20MiB 제한·중복 해시를 검증하는 로컬 스크립트.

- 원인: 미확정. 형식과 크기 중 실제로 다른 값은 추가 조사하지 않았다.
- 조치: 사용자 요청 “단계별로 통과하면 다음으로 넘어가고”, 이전 “안될 시 그냥 멈추기”에 따라 즉시 중단했다.
- 수리·변환·재다운로드·재검증: NOT_RUN.
- 새 미리보기: SKIPPED_AFTER_FAILURE.

## 재개 중 검증 코드 오류

- 세 파일의 실제 판독 형식은 MPO, 크기는 1536×2048로 확인했다.
- PNG 사본 검증 중 `decoded.convert("RGB").tobytes()`로 이미지를 읽은 다음 같은 객체에 `decoded.verify()`를 호출했다.
- 결과: `RuntimeError: verify must be called directly after open`. 검증 스크립트의 순서 오류다.
- 첫 PNG 사본을 생성했지만 전체 입력 전처리/manifest 완료 판정은 하지 않았다. 원본은 변경하지 않았다.
- 요청된 중단 규칙에 따라 후속 수정·재검증·생성·평가를 실행하지 않았다.


## 2026-10-23 · 검증 코드 수정 후 실제 1회 생성·평가 완료

- 사용자 지시가 수정됐다. 검증 코드 오류는 고치고 계속하며, 미리보기 확인 후 실제 1회만 호출한다. 앞선 FAILED_STOPPED는 당시 상태로 보존한다.
- MPO 원본 3개를 보존하고 frame 0을 PNG로 옮겼다. 새로 연 파일의 verify() 후 다시 열어 픽셀을 비교했다. 형식·크기·픽셀 일치·원본 해시 검사가 모두 통과했다.
- 제품 설명 길이를 계약 한도에 맞추고, 정면·측면·뒷면을 제품 입력으로 지정했다. Langfuse vivid-pop v1을 고정했다. 미리보기 HTML·파일·최종 프롬프트를 로컬에서 확인했다. 브라우저 로컬 파일 접근은 차단되어 브라우저 표시 검증은 하지 않았다.
- 실제 1회 성공: 27.393523초, 1152×1440. 사용량 5,298토큰. 현행 공식 요금 추정 $0.050008, 실제 청구액 null. 예약 $1은 사용액이 아니다.
