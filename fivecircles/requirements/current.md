# 현재 요구사항

## 제품

화장품 광고 생성 MVP의 텍스트/이미지 모델 계약과 구현을 실제 서비스에 연결한다.
2026-10-22 사용자 정정에 따라 **텍스트 담당 김다혜는 LLM·관찰·카피·영어 프롬프트, 이미지 담당 pi는 외부 이미지 API 래퍼·제품 보존·이미지 품질**을 맡는다. 이미지 생성·편집·누끼는 **OpenAI API**로 확정했다. B10은 실제 호출 없이 어댑터·영속 제출 기록·내부 API 연결을 구현한 배치다. 기본 모델 `gpt-image-2.5-sunburst-2026-09-08`, 허용 대안 `gpt-image-2-2026-04-21`을 허용한다. 이후 사용자 승인으로 MidProject 키를 사용한 기본 모델의 생성·편집·누끼3회가 성공했다. 시각 품질은 누끼 경계·제품 재구성 문제로 NOT_APPROVED이며 현재 팀 키 여부·청구액·실제품 품질은 미확인이다. 로컬 BiRefNetLite/SDXL은 실험 자료로 보존하며 자체 GPU 구축·튜닝·GCP CUDA 이전은 MVP 필수 조건에서 제외한다. 최종4:5·한글 합성·사용자 검토·참고 배경 구도 등 SSOT 기능 목표는 유지한다.

2026-10-22 사용자에게 받은 SSOT 문서 `401b13f77dbd80f39bbccd2e3a489566`를 MVP 목표의 대조 기준으로 사용한다. 수신본 SHA-256·현재 구현과의 차이·인수 조건은 [SSOT 대조 및 전달 기준](../../docs/ssotAlignment.md)에 기록한다.

- 동일 제품 사진 2~5장과 선택 배경 참고 사진 0~5장을 입력받는다. 배경의 모습과 구도 활용이 목표다. 세부 제품 카테고리 사전 선택을 요구하지 않는다.
- 기획 사전 조사 → 콘셉트·카피 1개 → 사용자 카피 검토 → 이미지 1개 → 사용자 이미지 검토 → 한글 카피 합성의 직렬 흐름을 목표로 한다.
- 최종 인스타그램 피드 광고 1개는 4:5이며, 캡션·해시태그와 확인·다운로드를 제공한다. 모델 작업 캔버스와 최종 출력 비율은 구분한다.
- 입력 용량·해상도 무제한이라는 SSOT 요구와 현재 20MiB·1,600만 픽셀 안전 상한 사이에는 운영 합의가 필요하다. 기존 가드를 자동 제거하지 않으며, 이 요구를 출력 비율 제한 없음으로 해석하지 않는다.
- 기존 로컬 누끼·제품 보존·제품 레이어 승인·ledger·요청 hash·유효 결과 캐시는 보존한다. OpenAI 결과는 단일 PNG이며 기존 세 레이어 승인·캐시를 자동 통과하지 않는다. API 누끼는 생성형이므로 픽셀·라벨 보존을 보장하지 않는다. 생성 후 사용자 이미지 검토·최종 한글 렌더는 별도 구현이다.
- 부분 수정 UI·다중 시안·3:4와 비율 선택은 후속이다. 실행 체크리스트의 원본은 [imageTodo.md](../../docs/imageTodo.md) 하나로 유지한다.

## 2026-10-23 B11 화장품 프롬프트

- 사용자 정정: 꽃은 이전의 제품 주제였다. 현재 화장품 프리셋에서 꽃을 반드시 넣으라는 조건만 제거한다. 꽃 사용을 금지하지 않으며 명시한 연출이나 참고 이미지에 따라 사용할 수 있다. 원래 패키지·라벨에 있는 그림은 제품의 일부로 보존한다.
- `CosmeticsPromptBrief`로 확인된 영어 제품 설명·연출 지시를 받아 클린 스튜디오·고급 미니멀·밝은 컬러 광고3개 프리셋에 조립한다. 김다혜의 LLM 생성·번역·카피 책임을 중복 구현하지 않는다.
- 첫 제품 사진의 시점·형태·라벨·색을 보존하고 뒤 제품 사진은 세부 확인 자료로 쓴다. 배경 참고의 다른 제품/문구는 복사하지 않는다. 브랜드색은 배경 강조색이다.
- 새 빌더는 `pipeline_revision="2"`를 선택한다. 기존 기본 revision1과 저장 snapshot/hash는 유지한다. 버전2 생성/편집은4:5이며 한글 문구는 빈 공간을 확보한 뒤 렌더러가 합성한다.
- B11은 키 조회·실제 API 추가 호출 없이 프롬프트/모의 전송을 검증한다. 프리셋·누끼 지시를 추가한 것은 실제 이미지 품질이나 팀 인수 완료가 아니다. [계약](../architecture/contract/cosmetics-prompts.md) · [사용 안내](../../docs/cosmeticsPromptGuide.md).

## 2026-10-22 B10 구현 이력

[OpenAI 계약](../architecture/contract/openai-images.md)에 따라 기본 `live_calls=False`·이미지 예산0, 고정 job당 POST 1회와 영속 제출 기록을 적용한다. 미확인 제출·과금은 자동 재시도/정산하지 않고 예약을 유지한다. 예약값은 실제 가격·청구액이 아니며 LLM과 공유하는 팀 계정의 잔액은 미확인이다. `usage`는 관찰하지 못하면 `null`이다. B10 배치에서는 실제 API·계정 권한·제품 품질 테스트를 하지 않았다. 후속 승인된3회 실행은 위 현재 상태와 구분해 기록한다.

`python -m beauty_ai.openai_images_demo --output outputs/openai-wrapper-demo`는 항상 mock이며 합성 fixture만 출력한다. [스키마 전달 초안](../../docs/schema-draft-2026-10-22/)은 보존하고 현재 `api_image` 계약과 구분한다. 새 요청 타입의 구현을 SSOT 전체 완료·팀원 인수로 확대하지 않는다.

## 2026-10-22 기존 B1~B9 구현 릴레이 기록

FiveCircles 초기화 후 plan/models TODO를 구현한다. 날짜는 마일스톤이며 준비된 작업은 먼저 진행한다. B1 자산/캔버스 → B2 영속 job/API → 이후 안전한 실행 단위를 검증·일반 push하며 연결한다. 실제 GPU와 계정 검증, 공동 합의는 별도 증거가 필요하다.

2026-10-22 B9 소스 `858c6f7` 및 전달 기록 `9f1d133`의 원격 게시·로컬 동기화를 확인했다. 전체624 tests와 실제 MPS 누끼1+배경5 jobs는 기존 로컬 엔진 검증이다. 당시 최종 HTML 브라우저 검증은 **BLOCKED**이며 그 상태는 유지한다. B9 기록은 이후 별도 요청한 B10 오프라인 API 래퍼나 전체 MVP 인수의 검증 근거가 아니다. [B9 증거와 한계](../test/relay-b9.md)를 따른다. 로컬 기술 검증을 광고 품질·GCP·노션 반영·다른 담당자의 인수 완료로 확대하지 않는다.

## B9 이후 SSOT 문서 전달 이력

사용자 요청에 따라 SSOT-01~12의 차이·목표·변경 작업·담당/미정·의존성·완료 기준을 [대조 문서](../../docs/ssotAlignment.md)와 기존 TODO에 연결한다. 이 문서 작업은 B9 종료 게이트를 건너뛰는 후속 구현이 아니며 추가 코드·모델 호출을 포함하지 않는다. HTML 검증 제한을 기존 승인된 소스·문서 게시 금지로 확대하지 않고, 최종 Git 게시 증거는 별도 갱신한다. 당시에는 브라우저 우회와 릴레이 다음 구현을 진행하지 않았다. 이후 별도 사용자 요청의 B10 오프라인 구현은 위 범위로 구분하며 HTML BLOCKED를 해제하지 않는다. 원문 파일·개인 경로·계정 정보는 공개 저장소에 복사하지 않는다.
