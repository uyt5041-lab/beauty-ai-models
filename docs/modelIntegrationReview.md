## 검토 자료와 결론

사용자가 추가로 제공한 노션에서 **김다혜의 실제 텍스트 모델 TODO와 접힌 1~4주차 상세 항목까지 확인**했다. 이번 비교는 이 원문과 [imageTodo.md](imageTodo.md)를 기준으로 한다. 기존 [llmTodo.md](llmTodo.md)는 pi 기준의 로컬 참고 체크리스트이므로 실제 팀원 담당·일정과 구분한다.

아래의 **원문 사실**은 문서에 적힌 계획이며 구현 완료나 파트 간 합의 완료의 증거는 아니다. **조정안**은 로컬 이미지 계획에 반영한 제안이다. 팀원 노션과 구현 코드는 변경하지 않았다.

**담당 역할은 나눌 수 있지만, 기존 이미지 계획에는 팀원 산출물보다 이른 계약/통합 날짜와 영어 프롬프트 전달 계약의 누락이 있었다.** Safe Zone 합의가 통합 뒤에 있는 점과 1차 문구 검수의 처리 방식은 아직 공동 합의가 필요하다.

## 10/26 교차 계약에서 결정할 항목

- [ ] **분석 JSON:** 필드명·타입·언어·필수 여부, 정상/미확인/실패 상태, 불확실성·출처·제품 revision을 정한다. 실패 시 편집용 초기값을 쓰더라도 제품 사실·효능으로 확정하지 않는다.
- [ ] **프롬프트 산출물:** 영어 positive/negative 필드의 사용 여부, 무드·콘셉트 매핑, 생성 모델/프롬프트 버전, 입력 revision을 정한다. 이미지 모델·파이프라인·해상도 결정 권한은 별도로 유지한다.
- [ ] **길이 처리:** 실제 선택한 파이프라인/tokenizer로 길이와 잘림을 확인한다. 원문의 약 77토큰 메모를 모든 이미지 모델의 검증된 공통 상한으로 사용하지 않는다. 필수 지시가 잘리면 재작성·오류 등 처리 방식을 합의한다.
- [ ] **레이아웃:** 기본 Safe Zone의 위치·크기·좌표계, 제품 영역, 템플릿 버전, 헤드/서브/CTA 길이 제한을 정한다. 프롬프트의 여백 지시만으로 좌표가 보장된다고 보지 않고 결과 이미지도 검사한다.
- [ ] **요청 hash·캐시:** 실제 사용한 영어 프롬프트와 관련 버전이 입력을 바꾸면 hash에도 반영한다. 현재 스키마에 해당 필드가 모두 구현돼 있다고 가정하지 않는다. 의도적 재생성과 응답 유실 재시도를 구분한다.
- [ ] **M1 검수·승인:** 1차 규칙 검사 결과의 범위·버전·상태와 내보내기 승인 주체를 정한다. 기존 `ReviewService`의 LLM 검수 전제와 연결 방식을 합의하고, 가드를 우회하거나 `unavailable`을 `no_flags`로 바꾸지 않는다.
- [ ] **11/02 이후 변경:** 규칙·LLM 프롬프트·레이아웃이 바뀌면 어떤 기존 문구를 재검수하고 어떤 이미지를 재생성할지 정한다. 인터페이스 필드가 같아도 내용·버전 변경의 영향을 확인한다.
- [ ] **인수 예제:** 정상 1건, 분석 실패/미확인, 긴 프롬프트, 문구만 수정, 레이아웃 변경, 새 이미지 요청, 응답 유실, 늦은 결과를 공통 예제로 남긴다.

현재 코드의 `CopyVariant`/`VisualBrief`에는 별도 영어 프롬프트·해당 버전 전달 계약이 완성돼 있지 않다. 위 항목은 **구현 전 합의 대상**이며, 이 문서 작성으로 adapter·스키마 변경이 구현된 것은 아니다.

## 충돌하지 않는 흐름과 공통 연동 예제

| 사용자/시스템 상황 | LLM 처리 | 이미지·서비스 처리 |
| --- | --- | --- |
| “문구만 더 짧게 바꿔줘.” | 문구 revision 갱신 후 재검수 | 비주얼 입력과 레이아웃이 같으면 기존 이미지 재사용. 문구는 렌더러에서 변경 |
| “제목을 위로 옮기고 제품 크기를 바꿔줘.” | 문구/옵션 검수 snapshot 변경 여부 확인 | `VisualBrief`의 영역·템플릿 변경을 반영해 이미지 key를 다시 계산하고, 필요하면 새 요청/작업으로 생성 |
| “배경을 다른 느낌으로 다시 만들어줘.” | 새 콘셉트가 필요할 때만 갱신 | 변경된 콘셉트/프로파일/seed를 새 요청에 고정하고 새 작업 ID 사용 |
| GPU 제출 요청의 응답이 유실됨 | LLM 재호출과 별개 | 같은 작업 ID로 상태 조회. 새 ID로 무조건 중복 제출하지 않음 |
| LLM의 제품 분석이 실패함 | 실패/불확실성과 편집용 기본값을 구분해 반환 | 확인된 사실로 자동 승격하지 않고 필수 입력 부재 시 수동 확인 또는 중단 |
| 새 영어 프롬프트를 수신함 | 무드/콘셉트와 버전·입력 revision 전달 | 길이·파이프라인 적합성을 확인하고, 실제 이미지 입력이 달라지면 request hash 갱신 |
| 문구 검수는 통과했지만 제품 라벨이 훼손됨 | 문구 검수 결과는 문구의 근거로만 사용 | 이미지 승인은 보류하고 재생성/수동 수정. 최종 내보내기 차단 |
| 편집을 바꾼 뒤 이전 생성 결과가 도착함 | 현재 문구/옵션 revision 유지 | 이전 작업에 결과를 남기되 현재 편집을 덮어쓰지 않음 |

문구 재작성 횟수와 이미지 재생성 횟수는 서로 다른 작업별 한도다. 하나의 무한 재시도 루프로 합치지 않는다. 이미지에 카피를 굽지 않는 원칙, 문구만 바뀔 때 불필요한 GPU 호출을 막는 원칙은 두 TODO에서 일치한다.
