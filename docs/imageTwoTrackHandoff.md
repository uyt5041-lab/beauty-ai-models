# 2트랙 이미지 연동 제안·담당별 전달문

2026-11-05. 이미지 Python 경계는 구현·오프라인 검증 완료. 서빙/프론트 연결·HTTP 계약·실제품 품질·배포/공동 인수는 남았다. 아래 담당은 기존 분담 기준의 제안이며 상대 담당자의 수락 완료를 뜻하지 않는다. [이미지 호출 방법](imageTwoTrack.md).

## 구성·공통 계약

| 총 장수 | 구성 | 후보별 job_id 예 |
|---|---|---|
| 1 | 자유형 또는 합성형 하나 선택 | free-1 또는 composed-1 |
| 2 | 자유형1 + 합성형1 (1:1) | free-1, composed-1 |
| 3 | 자유형2 + 합성형1 (2:1) | free-1, free-2, composed-1 |
| 4 | 자유형3 + 합성형1 (3:1) | free-1, free-2, free-3, composed-1 |

실제 job_id에는 배치 식별자를 포함해 후보마다 고유하게 고정한다. 위 짧은 예시를 다른 배치에서 그대로 재사용하지 않는다. 이미지는 호출당 후보1개·n=1이다. 장수 계산·후보 생성/실행·동시성은 서빙이 담당한다. ‘같이 생성’은 한 작업에서 결과를 묶는 뜻이며 완료 시각 일치를 보장하지 않는다. 자유형 후보끼리 다른 콘셉트/결과를 보장하지 않는다.

같은 제품 사진·참고 사진·제품 분석·승인된 전체 AdCopyOutput·copy_revision·비율을 공유한다. copy_hash는 전체 snapshot의 canonical content_hash다. 기획이나 카피를 후보 수만큼 새로 생성하지 않는다. job_id만 후보별로 구분하고 generation_mode=freeform/composed를 고정한다. 같은 job_id의 방식/사진/카피/비율 변경은 충돌로 거절한다. 방식 생략은 기존 단일 합성 경로다.

## 서빙 담당 전달문 — 이형기님

이미지 쪽은 BackendImageAdapter.generate(BackendImageInput(...), project_id=...)로 후보 하나씩 받을 수 있습니다. 새 입력은 generation_mode이며 freeform일 때 전체 copy_output이 필수입니다. copy_output의 canonical hash와 copy_hash, ad_copy/caption/hashtags가 일치해야 합니다. 기존 ProductAnalysisResult·한국어 image_prompt(문자열 또는 구조형)·사진 순서·revision 계약은 유지합니다.

총2/3/4장일 때 자유형1/2/3장과 합성형1장을 서버에서 계산해 고유 job_id로 요청해 주세요. batch_id·candidate_id·총 장수와 상태의 외부 HTTP 필드명은 아직 확정하지 않았고 이번 이미지 DTO에 추가하지 않았습니다. 후보 목록/순서·상태·소유 프로젝트·카피/이미지 승인 snapshot·선택/다운로드 hash를 기존 JobStore에 연결하는 작업이 남았습니다.

생성 결과의 receipt에는 generation_mode·attempt_id·provider_request_id·usage·상태가 있습니다. 성공 결과는 재조회하고, failed/unknown/submitting을 자동 새 요청으로 바꾸지 않습니다. 미확인 호출·저장 실패는 원장/요청 ID/자산을 대조한 뒤 상태와 예약을 종결해 주세요. 로컬 합성 실패는 생성 bytes로 export만 다시 합니다. shared account 예산/진행중 예약·총장수 제한·동시성은 서빙에서 실제 연결해야 하며, 같은 금액을 두 원장에서 중복 예약/차감하지 않게 합의가 필요합니다.

신뢰된 후보에 export_candidate(candidate, copy_output=approved_output)를 호출하면 자유형은 폰트/박스 없이 resize-only입니다. 합성형은 layout과 서버 font_path를 함께 넣습니다. 생성 원본과 최종 파생 PNG를 구분해 저장하고 실제 최종 파일 hash에 승인/다운로드를 묶어 주세요. export는 자체 인증/승인 기록을 만들지 않습니다.

## 프론트 담당 전달문 — 권혁상님

총1~4장, 단독1장일 때 방식, 비율/릴스·스토리 선택을 기존 서빙 API에 전달하는 UI가 필요합니다. 총2/3/4장은 각각1:1·2:1·3:1 구성을 안내하고 예상 비용은 추정값이라고 표시해 주세요. 신규 HTTP 필드명은 서빙과 맞춘 뒤 반영하면 됩니다. provider n값이나 이미지 제공자 키는 프론트에서 다루지 않습니다.

후보별 고정 순서·방식 라벨·진행/실패/미확인·결과·개별 선택/승인·다운로드를 연결해 주세요. 일부 성공은 유지하고, 새로고침/중복 클릭으로 새 유료 요청을 만들지 않게 기존 후보를 재조회해야 합니다. 거절 후 수정/임시저장 고도화와 후보 비교 생성은 다른 기능이므로 완료 상태를 따로 확인해 주세요.

## 텍스트 담당 전달문 — 김다혜님

제품 분석·기획·카피 검수는 기존 텍스트 결과를 후보 전체가 공유합니다. 한국어 prompt 또는 concept/prompt/mood 형식과 원문은 유지합니다. 자유형용은 광고 연출 프롬프트, 합성형용은 글자 없는 배경 프롬프트로 나눠 전달하는 문안을 맞춰 주세요. 현재 이미지 입력에는 프롬프트 하나가 들어가므로 서빙이 후보 방식에 맞는 값을 골라 전달하면 됩니다. text 생성 로직/새 결과 스키마는 이번 이미지 코드에서 변경하지 않았습니다.

승인 전체 copy_output과 ad_copy/caption/hashtags·revision/hash를 일치시켜 주시면 자유형에는 헤드·서브·허용된 CTA만 넣고, 합성형은 기존 한글 폰트로 합성합니다. 플랫폼 CTA 프로필에서는 이미지 CTA를 생략합니다. 본문/해시태그는 이미지에 넣지 않습니다. 자유형의 실제 글자 정확성은 텍스트 검수 통과만으로 보장되지 않아 최종 이미지 확인이 필요합니다. 배경 전용의 ‘문구 영역을 비워라’ 지시를 자유형에 그대로 재사용하는 품질 문제를 피하도록 문안을 구분하면 됩니다.
