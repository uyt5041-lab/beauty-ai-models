# W&B·비용·이미지 검수 작업 예시

이 문서는 두 가지 일을 설명한다. 먼저 저장된 W&B 기록을 확인한다. 다음으로 가상 자료로 비용과 검수 판정을 연습한다.
짧은 문장과 같은 용어를 사용했다.

**아래 계산 예시의 숫자·사람·제품·해시·시각·검수는 모두 가상이다.** 실제 20개 실험이나 팀 실적에 더하지 않는다. `confirmed`와 `true`도 예시 안에서는 계산을 위한 가정이다.
예시 실행기는 API를 호출하지 않는다. W&B에 자료를 올리지 않는다. 광고와 서비스도 승인하지 않는다.

| 용어 | 뜻 |
| --- | --- |
| FinOps | 비용을 확인하고 예산을 지키는 작업 |
| `null` | 아직 모르는 값. 0이 아니다 |
| `BLOCKED` | 필요한 근거가 없어 보류 |
| `FAIL` | 확인한 조건이 기준에 미달 |
| `PASS_PROVISIONAL` | 입력한 기록이 임시 수치 기준을 충족 |
| `NOT_GRANTED` | 승인하지 않음 |

## 1. W&B에서 밝은 컬러 광고 두 버전 비교하기

**목표:** 원본, 프롬프트와 결과의 차이를 확인한다.

**입력:** [저장된 20개 실행의 비교 화면](https://forge.coreweave.com/wandb/uyt5041-alphaflower/beautyai-image-experiments/runs/overview-ce25166dc920554527ea)을 연다. 접근 권한이 있는 계정으로 로그인한다. 이 절은 기존 기록을 읽는 작업이다.

**실행:** `api_comparison` 표에서 `prompt_name`이 `beautyai/cosmetics/vivid-pop`인 행을 찾는다. `prompt_version` 1과 2를 나란히 본다.

| 확인할 항목 | 화면의 필드와 확인 방법 |
| --- | --- |
| 원본과 결과 | `original_input`, `result`를 본다. `run_url`의 `image-experiment` 자료에서 전체 파일과 해시도 확인한다 |
| 실제 사용한 문장 | `prompt_text`를 비교한다. `langfuse_url`은 해당 프롬프트 관찰을 여는 링크다 |
| 제품 보존 | 원본의 형태·라벨·색·무광 재질이 유지됐는지 본다. 눈에 보이는 결과를 별도 검수 기록에 남긴다 |
| 실행 시간 | `elapsed_seconds`와 `timing_scope`를 함께 본다. B12의 job·대기·다운로드 구간과 B13의 processor 구간은 다르다 |
| 비용 근거 | `estimated_cost_usd`, `estimate_origin`, `actual_cost_usd`, `billing_status`를 함께 본다. 실제 청구액이 `null`이면 확정 지출로 쓰지 않는다 |
| 평가 상태 | `quality_status`와 `review_notes`를 본다. 업로드 성공이 광고 품질 통과를 뜻하지 않는다 |

**예상 결과:** v2가 원본의 무광 재질을 보존하도록 바꾼 문장과 그 결과를 확인할 수 있다. 더 짧은 시간이나 낮은 비용만으로 좋은 버전이라고 정하지 않는다.

**다음 행동:** 같은 조건으로 비교할 항목을 정한다. 원본·결과·버전을 묶어 두 사람이 검수한다. 새로운 이미지 생성은 별도 작업이다.

## 2. 새 실행 기록은 준비한 뒤 확인하고 올리기

**목표:** 저장된 실행 자료를 확인한 뒤 W&B에 올린다. 이미지를 다시 만들지 않는다.

**입력:** 지원하는 형식의 실제 run 폴더가 필요하다. 현재 수집 대상과 설치 방법은 [W&B 안내](wandbExperiments.md)를 따른다. 다음 명령은 실제 실험 `outputs/`가 있는 `beautyAi` 폴더에서 실행한다. 프로젝트 Python 환경을 사용한다.

**실행 1 — 오프라인 준비:**

```sh
python -m beauty_ai.wandb_experiments \
  --project-root . \
  --output outputs/wandb-experiments/next-review
```

`prepared.json`의 건수와 비용 근거를 확인한다. 원본과 결과가 맞는지 본다. 키·개인 자료·가상 검수 결과가 들어 있으면 먼저 고친다. 이 문서의 가상 계산 예시는 업로드 대상이 아니다.

**실행 2 — 내용을 확인한 뒤 업로드:**

```sh
python -m beauty_ai.wandb_experiments \
  --project-root . \
  --output outputs/wandb-experiments/next-review \
  --entity uyt5041-alphaflower \
  --project beautyai-image-experiments \
  --publish
```

두 번째 명령은 W&B에 자료를 쓴다. 이 문서를 만든 작업에서는 실행하지 않았다.

**예상 결과:** 기본 명령은 `PREPARED`를 남긴다. 업로드 후 파일을 다시 읽고 비교한 결과는 `upload-receipt.json`에 남는다. `READBACK_VERIFIED`가 완료 상태다. 중간 실패는 완료로 세지 않는다.

**다음 행동:** receipt의 `overview_url`을 열어 비교표를 확인한다. 같은 ID의 자료가 달라 충돌하면 새 ID로 숨기지 않는다. 원본과 receipt부터 확인한다.

## 3. 가상 계산 예시를 한 번에 실행하기

저장소 루트에서 실행한다. 설치된 테스트 환경이나 프로젝트 Python 환경을 사용한다.

```sh
python examples/evaluation/run_worked_examples.py \
  --output-dir outputs/worked-examples/first-run
```

경로를 바꿀 수 있다. 결과는 `outputs/` 폴더 아래에만 저장한다. 같은 이름의 결과가 있으면 덮어쓰지 않는다. 다시 실행할 때 새 폴더 이름을 준다.

실행기는 [가상 입력 JSON](../examples/evaluation/worked-examples.json)을 읽는다. 공개 함수 `evaluate_finops()`와 `score_image_case()`를 사용한다. 예상 상태·점수·이유가 맞는지도 검사한다.

| 결과 파일 | 용도 |
| --- | --- |
| `worked-examples.results.json` | 계산 결과와 상태를 기계가 읽는 파일 |
| `worked-examples.results.html` | 쉬운 한글로 읽는 결과 화면 |

`원가·낭비·예산`의 기준은 [임시 평가 계획](imageEvaluationPlan.md)을 따른다. 이 예시들은 FinOps 또는 이미지 **한 영역**만 계산한다. 종합 점수는 계산하지 않는다. 종합 비중은 이미지 40%·FinOps 40%·서비스 20%이며, 필요한 근거가 없으면 보류한다.

## 4. 청구와 잔액을 모르면 보류한다

**목표:** 모르는 비용을 0달러로 처리하지 않는다.

**입력:** 광고 10장과 예상 비용 4달러를 가정한다. 실제 청구액과 공유 잔액은 `null`이다.

**실행:** `evaluate_finops()`가 필수 근거를 확인한다.

**예상 결과:** `BLOCKED`. 실제 광고당 원가와 점수는 `null`이다. 예상 광고당 비용 0.40달러만 따로 남는다.

**다음 행동:** 팀 키와 공유 잔액을 확인한다. 청구 내역과 영수증을 맞춘다. 확인한 값을 넣고 다시 계산한다.

## 5. 가상 비용 조건을 모두 맞춘다

**목표:** 임시 FinOps 기준의 통과 조건을 확인한다.

**입력:** 광고 10장, 전체 생산비 4달러, 낭비 0.20달러를 가정한다. 팀 공유 사용액은 12달러, 잔액은 18달러다. 영수증 12개를 모두 대조한 것으로 둔다. 잔액은 평가 1분 전에 조회한 것으로 둔다.

**실행:** `evaluate_finops()`가 네 비용 조건을 계산한다.

**예상 결과:** `PASS_PROVISIONAL`, FinOps 100점. 광고당 비용은 0.40달러, 낭비는 5%, 팀 예산 사용은 40%다. 전부 가상 계산이다.

**다음 행동:** 실제 증거를 확인한다. 이미지 품질과 서비스 평가를 따로 마친다. 이 결과는 팀 인수나 유료 호출 허가가 아니다.

전체 생산비에는 LLM·이미지·유료 저장 등 가변비를 넣는다. 공유 OpenAI 비용은 그 안의 일부다. 계획된 연구비는 따로 표시한다. 인수한 광고가 0장이면 광고당 비용은 `null`이다.

## 6. 원가·낭비·예산 기준을 넘는다

**목표:** 잔액이 있어도 중단선에 도달하면 실패하는지 확인한다.

**입력:** 광고 10장, 생산비 6달러, 낭비 1.20달러를 가정한다. 팀 공유 사용액은 28달러, 잔액은 2달러다.

**실행:** `evaluate_finops()`가 광고당 0.50달러, 낭비 10%, 예산 사용 90% 기준을 확인한다.

**예상 결과:** `FAIL`, FinOps 25점. 광고당 0.60달러, 낭비 20%, 예산 사용 약 93.3%다. 청구 대조 항목만 통과한다. `BLOCK_NEW_PAID_CALLS`가 남는다.

**다음 행동:** 실제 작업에서는 새 유료 호출을 중단한다. 낭비 원인을 고친다. 예산과 호출 한도를 다시 확인한다. 이 함수는 상태만 계산하므로 실제 차단 장치는 별도로 필요하다.

## 7. 총점이 높아도 제품이 바뀌면 실패한다

**목표:** 제품 보존 오류를 높은 평균 점수로 숨기지 않는다.

**입력:** 가상 검수자 A와 B가 형태 2점, 나머지 네 항목 5점에 동의한 것으로 둔다. 두 사람 모두 제품 정체성이 바뀌었다고 표시한다. 실제 사람과 이미지는 없다.

**실행:** `score_image_case()`가 두 검수 기록을 계산한다. 이미지 파일을 읽어 품질을 판단하는 기능은 아니다.

**예상 결과:** 총점 85점이어도 `FAIL`. 형태 보존 기준 4점에 못 미친다. 제품 정체성 변경도 치명적 오류다. `asset_approval`과 `service_release_approval`은 `NOT_GRANTED`다.

**다음 행동:** 실제 작업에서는 원본과 결과를 나란히 확인한다. 보존 조건을 고친다. 이 합성 예시를 실제품 평가 20건에 넣지 않는다.

## 8. 검수 의견이 다르면 평균을 내지 않는다

**목표:** 의견 차이를 보류 상태로 남긴다.

**입력:** 가상 A는 색·재질 4점, B는 3점을 준 것으로 둔다. 다른 점수는 4점이다. 합의 기록은 없다.

**실행:** `score_image_case()`가 두 기록의 차이와 합의 유무를 확인한다.

**예상 결과:** `BLOCKED`, 점수 `null`. 3점과 4점을 임의로 평균 내지 않는다.

**다음 행동:** 두 사람이 같은 원본과 결과를 다시 본다. 합의 점수와 근거를 기록한다. 두 사람의 확인이 없으면 보류를 유지한다.
