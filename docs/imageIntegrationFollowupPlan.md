# 이미지 모듈 연동 후속 계획

작성일: 2026-10-29 · 담당: pi · 상태: 계획 수립, 구현 전

## 1. 목표

다혜님이 생성한 ImagePromptOutput·AdCopyOutput·ProductAnalysisResult를 그대로 받고, 휴대폰 원본 업로드부터 최종 한글 광고까지 재현 가능하게 연결한다. 제품 보존·배경과의 자연스러운 연결·카피 가독성·호출 비용을 이미지 담당 범위에서 관리한다.

## 2. 배경과 확인 범위

다혜님이 전달한 실행 보고: 롬앤 글로스 텍스트 결과(luna)를 BackendImageInput에 연결하여 1152×1440 이미지 생성, 약 49초. 입력 6,491토큰(사진 5,808 + 텍스트 683), 출력 418토큰, 비용 약 $0.06. 첨부 PNG의 실제 크기도 1152×1440이다.

이 수치는 팀원의 실실행 보고이며 이번 작업에서 같은 호출을 재현하지 않았다. $0.06은 보고된 추정 비용으로 저장하며 정산액·모델명·단가 버전은 미확인이다. 사진은 입력 토큰의 약 89.5%이며, 사진 비용 비중 75%는 단가와 캐시 구분이 있어야 확인할 수 있다.

MPO 첫 사진만 JPEG로 바꾸고 Windows의 디렉터리 동기화를 테스트에서 건너뛴 상태다. 따라서 원본 MPO/HEIC, 여러 사진의 원본 업로드, Windows 정상 저장, 최종 1080×1350 합성·다운로드는 이 보고만으로 완료 처리하지 않는다. 제품 보존도 원본·실행 JSON 대조 전에는 시각적 호평과 구분한다.

## 3. 범위와 역할

**이미지 담당:** 업로드 포맷 정규화, 저장 계층의 이식성, safe_zone의 실제 반영, 원형 보존·합성·그림자·재질 연결, A 템플릿, 실험 기록과 FinOps.

**텍스트 담당:** 광고 기획·카피·한국어 이미지 프롬프트·텍스트 검수. 이미지 쪽은 확정 카피를 재작성하거나 영문으로 번역하지 않는다. 콘셉트·소품 선택은 당장 실험의 이미지 연출 설정이며 텍스트 쪽 필수 스키마 변경으로 요구하지 않는다.

**서빙 담당:** 사용자 입력과 사진 역할 전달, 실행 ID·copy revision·상태·승인 결과 연결, 저장·다운로드의 실제 서비스 호출. 이번 계획은 서빙 API 경로를 임의 변경하지 않는다.

지금 제외: 추가 유료 생성, 로컬 누끼 모델 도입, 법률 검수 규칙 수정, 새로운 텍스트 생성기, 향상 기능을 MVP 연결 선행 조건으로 추가하는 일.

## 4. 기존 코드 접점

기준: 잇템 feat/image-generation `65c2e84`를 로컬에서 확인했다.

- `assets.py:put_upload`: 디코더 판별 포맷 PNG/JPEG/WEBP만 허용한다.
- `_normalize`: 애니메이션 또는 n_frames != 1을 차단한다. MPO를 포맷 목록에만 추가해도 다중 사진 MPO가 계속 막히므로 대표 이미지 선택 단계가 필요하다.
- `_normalize`: EXIF 회전·ICC→sRGB·RGB/RGBA 정규화·메타데이터 제거가 이미 있다. 이를 새 포맷 경로에서도 보존한다.
- `_sync_directory`: os.open(directory, O_RDONLY)와 fsync를 운영체제 분기 없이 수행한다.
- `_publish`: 임시 파일 flush/fsync → os.replace → 디렉터리 동기화 → SQLite 메타데이터 commit 순서다. 우회 때문에 이 계약을 약화시키지 않는다.
- `BackendImageInput.safe_zone`이 이미 선택 필드로 있다. 어댑터는 좌표를 한국어 지시에 붙이고 '이 영역에 제품을 배치하지 않는다'고 한다. 소품·반사광·복잡한 무늬의 억제는 현재 지시에 충분히 표현되어 있지 않다.

## 5. 핵심 결정

### 5.1 업로드는 넓게 받고, 내부 자산은 PNG로 유지

MPO는 지원하는 정지 사진 컨테이너의 대표 프레임 하나를 선택한다. MVP는 프레임 0을 기본 제안으로 두되 실제 휴대폰 표본으로 대표 영상인지 확인하고 선택 프레임을 기록한다. 추가 프레임을 별도 사진으로 몰래 보내거나 여러 장을 합치지 않는다. 일반 GIF/APNG 같은 애니메이션 허용으로 확대하지 않는다.

HEIC/HEIF는 검증한 Pillow HEIF 플러그인을 명시적으로 등록한다. 썸네일이 아닌 대표 원본을 선택하고 회전·ICC·색공간을 정규화한다. HDR/10-bit는 sRGB SDR 변환과 색 일치 여부를 시험한다. 지원되지 않는 조합은 성공으로 간주하지 않고 과금 전 업로드 오류로 돌려준다.

원본 바이트 해시·입력 포맷·선택 프레임·변환기 버전을 provenance로, PNG 해시·크기·mime을 기존 AssetRef로 구분한다. 외부 AssetRef의 `image/png|jpeg|webp` 열거형을 MPO/HEIC로 넓힐 필요는 없다. 저장 정규화 결과가 PNG이기 때문이다.

### 5.2 Windows 저장은 플랫폼 한계를 분리

Windows에서 지원하지 않는 디렉터리 fsync는 기능 지원 여부에 따라 별도 처리한다. 파일 flush/fsync, os.replace, DB commit은 유지한다. 전체 저장 작업의 PermissionError를 무시하거나 Linux 디렉터리 동기화를 일괄 제거하지 않는다. 실제 디스크·ACL·파일 쓰기 실패는 ASSET_STORAGE_ERROR로 남기고 자산을 게시된 것으로 반환하지 않는다.

Windows의 약해지는 디렉터리 내구성 보장은 내부 로그/문서에 명시한다. Linux 성공과 Windows 성공을 각각 테스트한다. 모의 os.name 테스트만으로 실제 Windows 완료를 표시하지 않는다.

### 5.3 safe_zone을 기본으로, 합성 보정을 보조로

결정: **생성 전 텍스트 자리 예약 + 생성 후 가독성 검사**. 그림자·박스는 보조 수단이며 장면 선택을 대신하지 않는다.

A 템플릿의 초기 제안:

```json
{
  "safe_zone": {"left": 0.06, "top": 0.04, "right": 0.94, "bottom": 0.25}
}
```

0~1 정규화 좌표이며 기존 단일 사각형 계약을 사용한다. 이미지 쪽 공통 지침에서 해당 영역에 제품뿐 아니라 소품·강한 하이라이트·복잡한 무늬도 피하도록 보강한다. 텍스트 담당의 80~200자 프롬프트에 모든 보존·안전 지침을 추가하도록 요구하지 않는다.

첨부 결과의 제품 맨 위는 눈대중으로 화면 상단 약 12% 부근이다. A의 상단 약 25% 문구 영역과 겹칠 수 있으므로 좌우 여백이 있다는 이유로 합성 준비 완료라고 보지 않는다. 이는 수동 시각 추정이며 자동 검출 결과는 아니다.

safe_zone은 모델에 대한 지시이지 픽셀 마스크 보장이 아니다. 생성 후 실제 제품/소품 침범과 배경 복잡도를 검사한다. 실패하면 적절한 전체 등비 프레이밍 또는 얇은 명도판으로 조정 가능한지 확인하고, 불가능하면 검토 필요로 반환한다. 자동 재생성하지 않는다.

CTA는 내부 A 레이아웃의 하단 공간·제품 보호 영역으로 관리한다. 첫 배치부터 BackendImageInput에 여러 safe_zone 필드를 새로 요구하지 않는다. 1152×1440은 4:5이고 최종 1080×1350도 4:5이므로 이미지 쪽 기존 resize_ad_png에서 등비 축소한다. 바이트 크기와 응답 width/height가 실제 파일과 일치하는지 확인한다.

## 6. 구현 배치와 완료 기준

### 배치 1 — 휴대폰 업로드·플랫폼 저장 호환 (연동 우회 제거 우선)

- [ ] MPO 대표 프레임 디코드 → 기존 정규화 파이프라인 연결
- [ ] HEIC/HEIF 플러그인 등록과 배포 의존성 고정
- [ ] 회전·ICC·알파·메타데이터 처리, 제한·손상 파일 방어 유지
- [ ] Windows 디렉터리 동기화 기능 분기. 파일 동기화·원자 교체·DB 계약 유지
- [ ] 일반 JPEG/PNG/WebP 회귀와 자산 해시·프로젝트 격리 검증

대상: assets.py, 관련 의존성 파일, 테스트 fixtures. 완료: 실제 또는 권리 확인된 MPO/HEIC를 수동 변환 없이 업로드하고 정규화 PNG를 다시 읽어 일치 확인. Linux·Windows 각각 저장/조회 확인. 실제 샘플이나 Windows 실행환경이 없으면 해당 항목은 NOT_RUN으로 남긴다.

### 배치 2 — safe_zone·A 최종 합성 고정

배치 1 이후 또는 독립 오프라인 구현 가능.

- [ ] A 템플릿에서 상단 safe_zone 생성, 미리보기에서 좌표와 카피 표시
- [ ] 기존 safe_zone 공통 프롬프트에 소품·광패턴·복잡도 억제 지시 추가
- [ ] 생성 결과의 실제 빈 공간과 제품 가림 검사
- [ ] A 폰트·좌표·최소 글자 크기·대비 설정을 서비스 합성기에 반영
- [ ] 1152×1440 → 1080×1350 PNG, 실제 확정 카피로 줄바꿈·가독성·다운로드 검사

대상: backend_adapter.py, 프롬프트 정책, composition.py, ad_resize.py, A 레이아웃 설정. 완료: 과금 없는 모의 생성으로 필드·좌표 전달 검사, 복잡한 배경에서 작은 그림자만으로 통과시키지 않음, 360px 표시와 응답/파일 크기 일치. 실물 결과 테스트는 별도 승인된 호출 또는 기존 팀원 결과를 재사용한다.

### 배치 3 — 제품 원형·배경 연결 품질

- [ ] 원본 대비 전체 비율·각도·뚜껑/본체 폭·재질·색의 검토 기준 정의
- [ ] 참고사진 편집 모드와 원본 누끼 고정 모드를 구분
- [ ] 외부 API 누끼 결과를 사진 해시로 캐시하고 같은 원본 재과금 방지
- [ ] 원본 누끼와 새 배경의 접지·그림자·광원·반투명 가장자리 검증
- [ ] 형상/품질 미달은 검토 필요로 표시하고 성공 응답만으로 품질 합격하지 않기

완료: 원본 누끼 합성의 변형 없음과 생성 편집 모드의 차이를 비교 가능하게 표시. 캐시 재사용·실패 시 추가 제공자 호출 없음 확인. 제품 원형을 보장하려면 이 배치를 핵심 품질 기준으로 적용하되 기존 단일 생성 연결 실험을 중단시키는 새로운 전제 조건으로 사용하지 않는다.

### 배치 4 — 배경·소품 실험과 FinOps 기록

- [ ] 텍스트 결과는 그대로 두고 이미지 연출 설정의 버전·카피 연결 이유 저장
- [ ] 카피의 핵심 단어별 의미 포함 여부 확인. 단순 어휘 유사도 평균으로 '봄' 누락을 덮지 않기
- [ ] 색·톤 / 제품 형태와의 관계 / 서체 / 콘셉트 / 소품을 각각 평가
- [ ] 원본·참고 사진 개수, 정규화 크기, 제공자 모델·화질·사용량·지연·추정/정산 비용 기록
- [ ] 사진 해시·누끼 캐시·중복 실행 방지·호출 상한 확인
- [ ] Langfuse 프롬프트 버전과 W&B 이미지/평가/비용을 동일 run_id로 연결

사진 입력 절감은 제품 보존 품질과 함께 평가한다. 원본 바이트를 보관하고 필요하면 제공자용 사본만 별도로 리사이즈한다. 먼저 근거 없이 사진을 줄여 2~5장 VLM 입력 계약을 바꾸거나 이미지 품질을 낮추지 않는다. VLM 분석용 사진 장수와 이미지 생성용 참조 장수도 구분한다.

## 8. 미확정/필요 자원

- 팀원이 사용한 원본 MPO와 iPhone HEIC 표본, 실제 실행 JSON·모델·단가 기록은 아직 받지 못했다. 이번에는 이미지를 첨부받았고 코드 경로를 확인한 범위다.
- 실제 Windows 실행환경과 HEIF 의존성 wheel/런타임 조합 검증 필요. macOS/Linux 모의 시험으로 대체 완료 표시하지 않는다.
- 제품 보존 임계값과 색차 측정 조건은 팀 합의 전 초안이다.
- 10/30 통합, 11/6 완성이라는 기존 일정은 목표다. 날짜 도래로 완료 체크하지 않으며 확인된 항목만 체크한다.

## 9. 다혜님에게 전달할 기술 결정 초안

실제 산출물을 이미지 모듈에 연결해 생성까지 확인해주셔서 감사합니다. 전달해주신 결과는 연동 근거로 기록하겠습니다. MPO·HEIC 정규화와 Windows 디렉터리 동기화 호환은 이미지 쪽에서 보완하겠습니다. 카피 영역은 기존 BackendImageInput.safe_zone으로 생성 전에 예약하고, 소품·강한 반사광도 해당 영역을 피하도록 이미지 쪽 공통 지침을 보강하는 방향으로 잡겠습니다. 생성 후에는 실제 카피로 대비·모바일 가독성을 검사하고 필요한 최소 합성 보정을 적용하겠습니다. 텍스트 프롬프트는 현재 계약대로 한국어 결과를 주시면 됩니다. 최종 출력은 이미지 쪽에서 1080×1350으로 맞추겠습니다.

위 문안은 사용자 검토용이며 팀원에게 전송하지 않았다.

## 12. 2026-10-30 실행 범위 정정

현재 사용자 지시에 따라 imageTodo 13절의 R1→R2→R3으로 진행한다.
기존 6절의 배치1에서 HEIC/HEIF를 분리한다. Windows는 협업 호환 구현이며 Linux 서비스 인수와 별도 판정한다.
MPO는 업로드 디코더가 MPO로 판별한 입력에서 frame0을 고르고 기존 정규화로 전달한다. 일반 애니메이션은 허용하지 않는다.
Windows에서 디렉터리 fsync를 생략하는 플랫폼 정책을 명시하되 파일 flush/fsync·os.replace·SQLite commit과 권한 오류는 그대로 유지한다.
외부 wire/AssetRef schema를 확장하지 않는다. 실제 사진/Windows/생성 API/서빙 E2E 증거를 각각 구분한다.
기존 제품 사진 두 장이 MPO임을 확인해 실제 로컬 업로드 시험에 사용한다. 원본과 생성 결과는 Git에 포함하지 않는다.
추가 유료 생성, 자동 원본 누끼 API, 디자인 고도화는 이번 구현에 포함하지 않는다.
