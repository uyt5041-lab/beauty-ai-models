## 다혜님께 공유할 문안

2. **보존 조건과 문구 역할:** 제품 폭·길이·캡 비율·원본 무광 재질·로고·라벨을 유지하도록 요청하겠습니다. 광고 카피는 중간 이미지에 새로 그리지 않고 최종 렌더러가 합성합니다. 원본 라벨 글자까지 지우는 지시가 되지 않도록 구분 부탁드립니다. 제품 보존은 품질 평가 대상이며 API의 보장으로 표시하지 않겠습니다.
3. **제품 유형:** SOT는 카테고리를 미리 선택하지 않는 흐름인데, `ProductFacts.product_type`은 필수로 되어 있습니다. 사용자 확정 사실과 AI 분석 유형을 어느 단계에서 채울지 혁상님과 함께 정하면 좋겠습니다. 임시값으로 검증을 통과시키기보다 단계별 의미를 먼저 맞추려 합니다.
4. **산출물 연결:** 승인된 콘셉트·카피와 영어 이미지 지시문·무드·프롬프트 버전이 같은 요청에 속한다는 것을 확인할 수 있게 필드 매핑을 정하고 싶습니다. 제품 사진 3장과 참고 사진 2장을 쓰는 예시 요청/응답 1세트, 수정한 스키마 버전, nullable/필수 필드 설명을 부탁드립니다. 사진의 역할·순서·참조는 서빙 계약과 연결하겠습니다.

저는 받은 예시로 이미지 래퍼의 오프라인 수신과 호출 전 미리보기를 확인하고, 누락 필드를 회신하겠습니다. 그다음 승인된 호출 제한 안에서 공동 실행 1건을 확인하고 프롬프트 버전·시간·사용량·추정 비용을 연결하겠습니다. 이미 구현한 내용이 있으면 해당 명세와 실행 결과를 알려주시면 그 기준으로 맞추겠습니다.

## 혁상님께 공유할 문안

혁상님, 프론트 체크리스트에서 MSW 기반 입력→생성 상태→결과 흐름 완료 표시를 확인했습니다. 이미지 API를 연결하기 전에 아래 항목을 같이 확인 부탁드립니다. 이미 화면에 반영됐다면 수정 대신 현재 화면이나 명세를 공유해 주셔도 됩니다.

1. **제품·참고 사진:** 최신 SOT는 동일 제품 사진 2~5장과 선택 참고 사진 0~5장인데, 완료 항목에는 제품 1~3장으로 적혀 있습니다. 화면과 API 검증이 어느 기준인지 확인 부탁드립니다. 제품/참고 사진을 구분해서 미리보기와 요청에 담고 역할·순서를 유지하려 합니다.
2. **제품 유형 입력:** 사용자가 카테고리를 미리 선택하지 않고 시작할 수 있게 다혜님과 입력 단계를 맞추면 좋겠습니다. 유형은 분석 결과인지 사용자 확정 정보인지 구분해 표시하려 합니다.
3. **검토와 최종 결과:** 카피 검토→이미지 1개 생성→이미지 검토→한글 최종 합성→4:5 광고 다운로드와 캡션/해시태그 흐름을 연결하고 싶습니다. 제품 비율 등은 안내하되 자동 재생성하지 않고 사용자가 결정하게 하겠습니다. 부분 보정은 현재 지원 여부를 표시하고, MVP 후속 기능을 구현된 것처럼 노출하지 않으면 좋겠습니다. 최종 합성 담당과 입출력도 같이 정해야 합니다.
4. **호출 전·후 상태:** 미리보기에서는 API를 호출하지 않습니다. 실제 생성 전 입력 사진·프리셋/버전·예상 비용·호출 상한을 확인하고, 실행 중 중복 제출과 결과 미확인 상태의 자동 재시도를 막는 흐름을 서빙 담당과 맞추면 좋겠습니다. 파일 축소·변환이 있으면 원본과 전송용 이미지를 구분해 안내하겠습니다. 정확한 상태 필드와 오류 코드는 공동 명세로 합의하려 합니다.

제품 2장/참고 0장, 제품 5장/참고 5장의 정상 예시와 장수 초과·실패·결과 미확인 상태 예시를 부탁드립니다. MSW와 실제 서버 결과를 구분해서 공유해 주세요. 저는 이미지 래퍼의 수신 검증·미리보기·결과 자산과 시간/비용 기록 연결을 맡겠습니다. 같은 작업 ID로 실제 E2E 1건을 확인한 뒤 공동 완료로 표시하면 좋겠습니다. 10/23 Mock E2E가 이미 수행됐다면 결과도 부탁드립니다.
