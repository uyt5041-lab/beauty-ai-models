# 이미지–서빙 연동: MVP·고도화·수정 요청

갱신: 2026-10-28 KST. 10/27 「이미지–백엔드 연동 재점검」의 W0~W6 분류를 유지한다. 서빙 소스는 새로 조사하지 않았다. 아래 서빙 상태는 **10/27 확인 시점**이며 최신 구현 완료를 대신하지 않는다. 요청문은 미전송이고 상대 수락·공동 인수는 미확인이다.

## 적용 기준

[10/26 회의](https://app.notion.com/p/2026-10-26-405b13f77dbd80eda3c8c2570a2cb82b)와 [공통 계약 v0.2 고정본](https://github.com/taemin050-sys/project-it-tem/blob/0b5bb47cf3f2daad1b12d0d4550f9e63a6a6c13c/docs/interface_spec.md)을 우선한다. 계약에 없는 내부 구현은 서빙 방식에 맞춘다. 새 HTTP 경로·상태 코드·직접 호출 함수 서명은 이 문서만으로 확정하지 않는다.

다혜의 [VLM 연동 문서](https://app.notion.com/p/VLM-406b13f77dbd8022a12ecbc41e584f8f)를 반영한 이미지 Python 수신 계약은 [textImageHandoff.md](textImageHandoff.md)다. 텍스트 생성·검수는 다혜, 이미지·최종 합성은 pi, 서비스 연결은 이형기, UI는 권혁상이다. Langfuse/W&B는 모델 내부에 둔다.

**MVP:** 단품 화장품 판별과 실패 중단, 두 사용자 검토, 현재 승인 대상 고정, 중복 호출 방지, 기본 실행 기록·예산 통제, 최종 한글 4:5 PNG·캡션·태그 다운로드.

**고도화:** 거절 후 편집·새 시안 재생성·재승인 UI, 세트/동일 제품 판별, 영어 프롬프트 변환. 자동 게시·릴스/캐러셀·복수 후보 탐색은 이번 MVP 밖이다. 같은 요청의 실수 중복 실행 방지는 고도화로 미루지 않는다.

## 서빙에 공유할 수정 요청 (미전송)

1. `product_analysis`에는 다혜님의 `ProductAnalysisResult.model_dump()` 결과를 전달한다. `analysis_succeeded=false`이면 다음 단계를 멈춘다. 성공한 경우에만 `is_cosmetic`을 확인한다. 실패 기본값 `is_cosmetic=true`로 통과시키지 않는다. 이미지 쪽도 방어적으로 다시 검사한다. 오류 코드는 `PRODUCT_ANALYSIS_FAILED`와 `PRODUCT_NOT_COSMETIC`이며 HTTP 매핑·사용자 문구는 서빙에서 맞춘다. 원시 `error`는 사용자·이미지 요청으로 보내지 않는다.
2. `image_prompt={concept,prompt,mood}`를 손실 없이 넘긴다. 사용자 입력을 반영한 다혜의 광고 무드다. 별도 원본 무드나 프리셋 선택은 요구하지 않는다. 이미지 내부의 `positive`는 한국어 prompt 원문으로 시작하고 조건을 뒤에 붙인다. `negative=""`, `language="ko"`이며 영어 번역 호출은 없다. VLM 제품 분위기로 광고 무드를 덮어쓰지 않는다.
3. 같은 분석 대상의 생성용 원본 사진 2~5장을 순서대로 전달하고 1번을 정면으로 유지한다. 참고 사진은 별도 0~5장이다. VLM용 축소본과 생성 원본을 구분한다. 분석 성공 bool만으로 사진 일치·사용 권한이 검증되지는 않는다.
4. 서비스 `job_id`와 승인된 카피 revision/hash를 고정한다. 같은 요청은 같은 ID로 조회/재사용하고, timeout·저장 실패 때문에 새 ID로 자동 재호출하지 않는다. 입력이 바뀌면 새 사용자 실행으로 다룬다. 텍스트 생성·검수는 다혜 모듈을 사용한다.
5. 반환 bytes와 MIME·실제 width/height·SHA, 기본 실행 기록을 서비스 작업에 저장한다. 모델·시도·사용량·시간·오류가 빠지지 않는지 확인한다. 모델 내부 관측 SDK나 Langfuse 프리셋 조회는 서빙에 붙이지 않는다.
6. 최종 결과는 파일을 열어 1080×1350인지 확인한다. 1152×1440 파일을 그대로 두고 JSON 치수만 1080×1350으로 쓰지 않는다. 리사이즈는 로컬 처리이며 별도 이미지 API 호출이 아니다. PNG 저장은 무손실이지만 축소 자체는 픽셀 정보를 줄인다.

서빙 수정 요청의 수락 여부는 아직 확인하지 않았다. 위 내용은 구현되어 있다고 표시한 부분 외에는 인수 조건이다. 상세 예제는 [백엔드 모델 어댑터](backendModelAdapter.md), 상태 체크는 [이미지 TODO](imageTodo.md)에서 관리한다.

## 다혜·혁상·PM에게 필요한 확인

- 다혜: 현재 제품 분석·한국어 prompt/concept/mood·구조화 카피·검수 결과의 실제 파일/커밋과 성공·실패 예제 제공. 프리셋 선택이나 영어 변환 요청은 하지 않는다.
- 혁상: 확정된 서빙 응답으로 검토·승인·다운로드 연결. 분석 실패 중단과 결과 미확인 표시. 편집/재생성 UI는 고도화로 유지한다.
- PM: 미확정 HTTP 세부사항·계정별 팀 예산 범위·공개 접속 방식·M1 실제 실행 범위 확인. 이미 확정된 정책을 새 제안으로 바꾸지 않는다.

기록 누락은 출력 스키마→전달/저장→FinOps 문제다. 중복 과금 위험은 FinOps와 상태·재시도 경계의 문제다. 관측 도구가 모델 내부에 있어도 서비스 실행 기록은 필수다.
