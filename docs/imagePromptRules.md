# BeautyAI 이미지 프롬프트 작성·리뷰 규칙

2026-11-04 · 팀 공유용 · 자유구도 광고 실험 기준 v1

제품 원본, 전달받은 한국어 카피·무드, 스타일 참고를 구분한다. 장면을 먼저 설계하고, 아래 17개 디멘션을 지정한 다음 결과를 같은 항목으로 검토한다.

이 문서는 이번 **자유구도 완성 광고 실험**의 작성 규칙이다. 제품·배경·문구를 한 번에 생성하는 실험과, 승인된 카피를 별도 합성하는 서비스 MVP 흐름은 구분한다. A 배치나 서비스 계약을 바꾸거나, 이 문서를 서비스에 자동 적용한 상태는 아니다.

## 1. 입력과 책임

| 입력 | 역할 | 옮기지 않을 것 |
| --- | --- | --- |
| 제품 원본 | 형태·폭/높이·각도·색·라벨·부품별 재질의 기준 | 다른 광고 속 제품의 용기·라벨 |
| Text팀의 카피·콘셉트·사용자 무드 | 의미와 표현 방향의 기준. 한국어 그대로 사용 | 이미지팀의 임의 번역·재작성·효능 추가 |
| R01 미샤 VITA B 광고 | 제품을 주인공으로 두고, 메시지를 빛·재질·형태로 보여주는 원리 | 핑크색·기포·젤을 모든 테마에 자동 추가 |
| R02 아이소이 잡티로즈 광고 | 인물·손·제품·강조색·글자의 연결 원리 | 실제 얼굴·동일 포즈·의상·문구·브랜드 주장 복제 |

R01/R02의 활용 원리는 우리 시각 해석이다. 공식 디자인 매뉴얼로 표시하지 않는다. **참고 2장은 구도 2개 제한이 아니다.** 테마·구도·서체의 변주는 별도로 설계한다.

이번 예시는 제품 원본 1장 → R01 → R02 순서다. 이전 생성 광고는 비교 기록일 뿐 입력에 넣지 않는다. 입력하지 않은 이미지를 모델이 본다고 가정해 “이전보다 1.4배”처럼 쓰지 않는다.

## 2. 먼저 정할 것과 우선순위

1. 카피가 전달할 의미와 사용자 무드를 확인한다.
2. 배경의 장소·소재·배색·톤·광원을 먼저 정한다. 다른 장면을 만든 뒤 색만 덮어 테마를 바꾸지 않는다.
3. 제품·인물·카피의 구도와 소품의 역할을 정한다.
4. 부품별 재질·광택, 서체의 형태·굵기, 모바일 읽기 크기를 정한다.
5. 정확한 카피와 제외 조건을 붙이고 17항목의 누락·충돌을 확인한다.

제품의 사실성과 수신 카피·무드를 지키면서 읽기와 여유 있는 프레이밍을 확보한다. 장식 때문에 제품을 변형하거나, 인물·문구를 억지로 잘라 넣지 않는다. 조건이 충돌하면 장식·배치부터 조정하고, 의미가 충돌하면 임의로 덮어쓰지 말고 확인한다.

## 3. 필수 디멘션 17개

모든 사례에 17개 설정과 리뷰 칸을 둔다. 인물이 없으면 눈 방향·손 관계·의상은 이유와 함께 비해당으로 기록한다. “소품 없음”은 유효한 소품 설정이다.

| ID · 디멘션 | 프롬프트에 정할 내용 | 결과에서 볼 것 |
| --- | --- | --- |
| `palette` 배색 | 제품·배경·문구의 주조색과 강조색 관계 | 제품과 배경이 구분되는가, 강조색이 과하지 않은가 |
| `product_color` 제품 고유색 | 원본 부품·라벨 색 유지 | 환경 반사와 실제 재도색을 구분했는가 |
| `tone` 톤 | 밝기·채도·따뜻함·차가움 | 밝은 화장품 톤인가, 회색기·탁함·과노출은 없는가 |
| `lighting` 광원 | 방향·부드러움·보조광·접촉 그림자 | 제품 앞면이 읽히는가, 사람·제품·배경의 빛이 일치하는가 |
| `material` 재질 | 불투명 본체·종이·유리·피부·천의 차이 | 주변 재질이 제품으로 전이되지 않았는가 |
| `gloss` 광택 | 부품별 무광·새틴·유광과 반사 범위 | 무광이 젖거나 유광이 무광으로 바뀌지 않았는가 |
| `geometry` 각도·비율 | 원본의 폭/높이·캡/본체·보이는 면·윗면 타원 | 두께 왜곡·회전·정면화·과도한 내려다봄이 없는가 |
| `concept` 콘셉트 | 카피·무드가 보이는 장소·질감·행동 | 색만 바꾼 것이 아니라 의미가 장면에 드러나는가 |
| `props` 소품 | 왜 필요한지, 무엇을 어디에 얼마나 놓는지 | 의미 없는 구슬·장식·그림자, 제품과의 경쟁은 없는가 |
| `place_truth` 사실 관계 | 지역·원료·연구 연출의 근거와 한계 | 미확인 산지·성분·임상·효능을 암시하거나 주장하지 않는가 |
| `composition` 배치 | 제품·인물·카피 크기와 여백, 의도한 크롭 범위 | 필요한 머리·어깨·손끝·제품이 답답하게 잘리지 않는가 |
| `attention` 관객 시선 | 제목→제품→설명→CTA 등 읽는 순서 | 얼굴·반짝임·소품이 메시지를 빼앗지 않는가 |
| `model_gaze` 모델 눈 방향 | 카메라·제품·화면 밖 응시와 목적 | 목적에 맞는가. 카메라 응시 자체는 결함이 아니다 |
| `interaction` 손·사용 연상 | 제품 종류에 맞는 손·얼굴·사용 부위 관계 | 손가락·관절·접지가 자연스럽고 라벨을 가리지 않는가 |
| `wardrobe` 의상 | 피부·의상·제품색과 소재의 관계 | 의상이 제품보다 강하거나 전부 같은 색으로 칠해지지 않았는가 |
| `typography` 글자 모양 | 고딕·세리프·손글씨 계열, 굵기·기울기·리듬 | 제품의 폭·자세·테마와 맞고 한글이 바로 읽히는가 |
| `mobile` 모바일 | 360px 폭에서도 읽히는 크기·대비·줄바꿈 | 서브·CTA를 확대 없이 식별할 수 있는가 |

색은 배색·제품색·톤으로, 표면은 재질·광택으로 나눠 쓴다. “밝고 고급스럽게” 한 문장으로 대신하지 않는다. 관객의 시선 흐름과 모델의 눈 방향도 별개다.

## 4. 이번 실험에서 얻은 구체 규칙

- **제품 보존은 부품별이다.** 이번 스킨푸드 통은 흰 불투명 무광·새틴 본체와 검은 유광 뚜껑이다. “제품 전체 무광”으로 쓰지 않는다. 원본 뚜껑의 넓은 반사도 유지할 수 있다.
- **각도는 원본의 보이는 면으로 지정한다.** “카메라를 높인다” 대신 원본의 뚜껑 타원·윗면 노출·라벨 곡면을 유지한다고 쓴다. 지나친 탑뷰로 바꾸지 않는다.
- **소품은 이유가 있을 때만 쓴다.** 의미 없는 구슬과 그림자를 지운 빈자리에 다른 장식을 채울 필요가 없다. 꽃은 기본 추가도 전면 금지도 아니다.
- **프레이밍은 인물·손·제품을 함께 조정한다.** 여유 있는 인물형에서는 카메라를 물려 머리·턱·양 어깨·손끝·제품 전체를 넣는다. 제품을 찌그러뜨리거나 비현실적인 손 크기로 맞추지 않는다.
- **사용 행동을 지어내지 않는다.** 닫힌 패드 통을 드는 것은 실제 패드를 바르는 장면과 다르다. 확인되지 않은 내용물·집게·성분·효능을 만들지 않는다.
- **서체도 테마별로 바꿀 수 있다.** 단정한 고딕, 편집형 세리프, 명료한 손글씨 등을 구분하되 한글 자형과 모바일 읽기를 우선한다. 픽셀만으로 정확한 폰트명·라이선스를 확정하지 않는다.
- **워터마크·서명을 새로 생성하지 않는다.** 원본 제품 로고·라벨은 보존한다.

제품폭 30~34%, 가장자리 6%, 특정 글자 픽셀 크기·대비값은 이전 실험의 제안값이며 전 사례의 확정 규격이 아니다. 자연스러운 손·얼굴·통의 크기 관계와 실제 모바일 검토를 우선한다.

## 5. 카피와 프롬프트 전달

Text팀 한국어 프롬프트를 받을 때는 영어로 번역하지 않는다. 서비스 `ImagePrompt`의 `positive`는 수신 한국어, `negative`는 빈 값, `language`는 `ko`라는 기존 방향을 유지한다. 이 가이드의 실험 예시를 받았다는 이유로 서비스에서 수신 `positive`를 몰래 재작성하지 않는다.

별도 합성 MVP에서 합의한 카피 입력 범위는 헤드 15자·1줄, 서브 총25자·한 줄15자·최대2줄, CTA 10자·1줄이다. 공백·문장부호는 세고 줄바꿈은 제외한다. 자유구도 실험의 좌표·서체를 이 규격으로 고정하지는 않는다.

Text팀이 보낸 의미 단위 줄바꿈을 보존한다. JSON의 `\n`은 파싱하면 실제 줄바꿈 1개다. `\\n`은 역슬래시와 n 문자로 남으므로 구분한다. 이번 예시 JSON은 실제 줄바꿈을 직렬화했다.

본문·해시태그는 별도 캡션으로 두며 이번 광고 이미지에는 지정된 헤드·서브·CTA만 넣는다. 이번 예시 카피는 기존 실험 문구의 재사용이며, 새 Text팀 산출이나 규제 승인 완료로 표시하지 않는다.

## 6. 작성 틀과 완성 예시

아래 순서로 작성한다. 17개 설정은 모두 명시하되 문장 순서는 장면에 맞게 묶을 수 있다.

```text
[결과] 비율·광고 목적·자유구도 또는 별도 합성 여부
[입력 역할] 제품 원본 / 스타일 참고 / 실제로 첨부한 입력만
[의미] 수신 카피·사용자 무드·선택한 콘셉트
[배경] 배색 / 제품 고유색 / 톤 / 장소·소재의 사실 관계
[빛과 표면] 광원 / 재질 / 부품별 광택
[형태와 배치] 원본 각도·비율 / 구도·여백 / 관객 시선
[인물] 눈 방향 / 손·사용 관계 / 의상. 인물 없으면 비해당 이유
[문구] 서체 형태 / 모바일 가독성 / 정확한 카피와 줄바꿈
[제외] 불필요한 장식·미확인 주장·문구 추가·워터마크
```

완성 예시는 **스킨푸드 · 여유 있는 데이라이트 루틴**이다. N05의 우측 어깨 크롭과 작은 서브·CTA를 보완하는 새 초안이다. 별도 사용자 무드 입력은 없어 실험 테마로 작성했으며, 향후 실제 사용자 무드가 오면 그 입력을 우선한다.

- [복사용 전체 한국어 프롬프트](../examples/prompts/daylight-roomy.v1.txt)
- [ImagePrompt JSON](../examples/prompts/daylight-roomy.v1.json)
- [입력 순서·해시·17개 설정·상태](../examples/prompts/daylight-roomy.v1.manifest.json)
- 2026-11-04 오프라인 검증 기록: TXT와 JSON `positive` 일치, 17개 항목·카피 줄바꿈·당시 로컬 `ImagePrompt` 스키마 검사 통과. 원본 검증 기록과 소스 스냅샷은 이 게시에 포함하지 않는다. 현재 배포 서비스의 검증 결과가 아니다.

TXT와 JSON의 `positive`는 같은 문자열이며 원본 바이트·버전을 그대로 공개한다. JSON에는 이미지 첨부가 포함되지 않는다. **사진은 이 저장소에 포함하지 않는다.** 실행하려면 사용자가 manifest에 적힌 제품 원본 1장과 스타일 참고 2장, 총 3개 파일을 별도로 준비하고 제품 → R01 → R02 순서로 전달해야 한다. 기록된 입력을 재현하려면 파일 SHA256도 일치해야 한다. `source_revision=1`은 복사용 예시 리비전이며 실제 서비스 승인 리비전이 아니다.

## 7. 결과 리뷰와 현재 상태

각 항목은 **적합 / 보완 / 미확인 / 비해당**으로 기록하고, 관찰·수정안·근거 이미지를 붙인다. 비해당에는 이유가 필요하다. 누락은 리뷰 미완료이며, 평균점수로 제품 왜곡·손 오류·카피 손상 같은 문제를 상쇄하지 않는다.

원본과 나란히 제품·재질·각도를 보고, 전체 이미지와 360×450 미리보기에서 크롭·읽기 순서·문구를 확인한다. 육안 적합을 정밀 색차·치수·OCR·접근성·폰트 권리·광고 성과 통과로 확대하지 않는다.

**2026-11-04에 문서와 프롬프트 초안을 오프라인으로 작성·검증했다. 새 이미지 API 호출·이미지 품질 검증·Langfuse 게시·서비스 연결은 수행하지 않았다. 문서 공개는 별도로 기록한다.** 예시의 각도·손·양 어깨 여백·서브·CTA 개선 성공은 다음 실제 출력에서 확인해야 한다.
