# 금붕어 리뷰: 제품 사진을 넣었는데 라벨이 달라지는 이유

**공유된 초안 검토이며 현재 서비스·팀 코드의 결함 판정이나 수정 요청이 아니다. 실제 실험의 최종 전송문은 미확인이다.**

이 문서는 기존 리뷰의 게시용 사본이다. 로컬 경로를 삭제하고 게시한 파일로 링크를 바꿨다. 비공개 사진·실행 기록·소스 스냅샷은 포함하지 않는다. 아래 결론과 F1~F4 상태는 당시 판정이며, 새 이미지 실행이나 팀원 요청 재현을 수행한 결과가 아니다.

## 결론

**공유 프롬프트에는 보완할 지시가 있다. 그러나 실제 팀원 실행의 원인을 프롬프트나 첨부 누락으로 확정할 수는 없다.** 제품 사진을 입력한 사실과 출력에서 라벨이 보존된 사실은 각각 확인해야 한다.

이번 대화에서 원본을 첨부하지 않은 첫 인물형은 별개 사례다. 이를 근거로 팀원도 원본 없이 생성했다고 말하지 않는다. 팀원의 image[] 사용 보고와 현재 로컬 코드의 첨부 처리를 구분한다.

2026-11-04 검토에서 참조한 OpenAI 공식 문서는 입력을 이용한 편집에서도 글자의 정확한 배치·명료성, 브랜드 요소의 일관성, 정밀 구도에 한계가 있다고 설명한다. 입력 이미지를 받는 것은 모든 픽셀을 고정 복사한다는 보장이 아니다. [공식 제한 사항](https://developers.openai.com/api/docs/guides/image-generation).

- 당시 로컬 openai_images.py와 contracts.py는 읽기만 했다. 해당 소스 스냅샷은 이 게시에 포함하지 않으며, 현재 공개 브랜치·팀원 코드·배포본과 동일하다고 간주하지 않는다.

## 최소 문장 보완안

아래는 제안이며 운영 프롬프트나 원문에는 적용하지 않았다. 정물형을 전제로 한다.

```text
제품의 원본 촬영 시점·실루엣·폭/높이·뚜껑/본체 비율·라벨 곡면과 모든 인쇄를 우선 보존한다. 새 조명이나 장면 배치가 이 조건과 충돌하면 장면 배치를 조정한다.

원본 제품에 이미 인쇄된 로고·외국어·용량·설명·표식은 그대로 보존한다. 이 기존 인쇄와 지정 광고 카피 이외의 글자를 새로 추가하지 않는다. 라벨을 요약하거나 새 글자로 재작성하지 않는다.

제목과 서브는 왼쪽의 한 묶음으로 읽히게 하고, 이어 제품으로 시선이 이동하게 한다. 카피와 제품 전체를 안전영역 안에 두는 것을 우선하며, 필요하면 제목의 의미 단위 줄바꿈과 간격·제품의 균일 배율을 조정한다. 제품의 폭만 바꾸지 않는다.
```

17개 항목의 개수 자체가 보존 품질을 보장하지 않는다. 상충하는 지시와 같은 내용을 덧붙이는 조립 규칙을 정리해야 한다.

## image[] 점검 결과

2026-11-04에 읽은 로컬 어댑터는 제품 사진이 있는 edit 요청을 multipart image[]로 직렬화한다. 제품 바이트를 먼저, 참고 바이트를 뒤에 둔다. _prompt는 경로에 따라 관리 프롬프트 또는 다른 빌더를 사용할 수도 있으므로 최종 전송 문자열 확인이 필요하다.

구조 검토의 최초 S1은 generate 경로에서 첨부가 빠질 가능성이었다. 후속 교차 확인에서 **당시 로컬 정상 검증 경로에서는 반증돼 철회했다.** execute→validate_input→validate_request→_snapshot 재검증을 거치며, 계약은 generate+제품 사진을 거부하고 edit에는 제품 사진을 요구한다. 이를 현재 코드의 결함이나 팀원 오류로 보고하지 않는다. 이 판단은 당시 소스의 고정 해시에 한정하며 팀원 실제 요청에는 적용하지 않는다.

팀원 실제 실행을 확인하려면 해당 결과와 연결되는 다음 정보가 필요하다. API 키·인증 헤더는 필요 없다.

- 실제 엔드포인트·모델·size·quality 등 옵션
- 코드가 고정 문구를 붙인 뒤의 최종 프롬프트와 버전
- 전처리 후 첨부 개수·순서·MIME·가로세로·SHA256 및 결과와 연결되는 요청 ID

당시 공식 입력 충실도 안내에 따르면 gpt-image-2는 입력을 항상 high fidelity로 처리하므로 input_fidelity를 생략하도록 공식 문서가 안내한다. 모델을 확인하지 않고 해당 옵션을 high로 추가하라는 처방은 하지 않는다. [공식 입력 충실도 안내](https://developers.openai.com/api/docs/guides/image-generation).

## 안전영역과 후처리 대안

이 프롬프트가 정한 위14%·아래40%·오른쪽10%를 적용하면 사용할 수 있는 세로 범위는 전체 높이의 약46%다. 1152×2048 예시에서 정수 픽셀 영역은 대략 x<1037, 287≤y<1229이다. **이 값은 공유 프롬프트의 실험 기준이며 릴스 모든 기기의 공식 고정 규격으로 검증한 값은 아니다.** 픽셀로 적어도 생성기가 정확히 지킨다는 보장은 없어 결과 검사가 필요하다.

| 선택지 | 쓸 조건 | 남는 한계 |
| --- | --- | --- |
| 프롬프트 최소 보완 | 현재 생성 방식을 유지하며 지시 모호함부터 줄일 때 | 라벨·글자·정밀 배치를 보장하지 않음 |
